# Cross-proof coherence check — "one launch, not twelve posts"

Read the drafted/published proofs together, with `BLOG-PLAN.md`'s arc. This is the freeq analog of the book's cross-chapter coherence pass: individual posts can each be strong and the *launch* still fail if they don't cohere into one cumulative argument in a single persistent world.

Report, defects first:

1. **Recurring cast.** Are the same identities (DIDs), rooms/channels, agents, and nodes reused across proofs, so they become recognizable characters? Flag any proof that invents a fresh demo universe instead of adding to the shared one — that's the primary defect this pass exists to catch.
2. **Back/forward links.** Does each proof link backward to the previous and forward to the next, and read as a numbered proof on the launch page? Flag orphans.
3. **The arc builds, in order.** Reveal (1) → inspect architecture (2) → verify identity (3) → watch an agent (4) → encrypt (5) → voice agent (6) → media bus (7) → pipe a live station (8) → policy (9) → revoke + rotate keys (10) → federate another world (11) → conversation-is-the-commit (12). Each post adds exactly **one** capability to the environment the reader already met. Flag any post that front-runs a later capability or re-does an earlier one.
4. **Experiment / field-notes rhythm.** One of each per week; experiments reveal, field-notes explain. Flag two adjacent posts doing the same job (the "clip-show" failure).
5. **The Phoenix endgame, earned.** Is the "freeq is the provenance layer *Regenerative Software* says nobody has built" thread building toward proof 12 without being stapled on early? Flag both failure modes: never set up, or over-explained too soon.

**Output:** a coherence report — each defect with the proof number and the fix.
